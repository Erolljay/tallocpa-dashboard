Suggested build order

SliceWhatWhen
W1Period file with lead schedules B–E read from approved documents and the ledger, plus the T tie-outs. Read-only; no new data entry.Before Jan 2027 go-live
W2Adjustments with reason and support replace “figures typed in”; per-schedule preparer and reviewer sign-off; “Mark prepared” gated.During the first live cycle
W3Review notes anchored to a schedule or row; open or cleared; replace the kick-back note. My work home for staff and reviewers.After cycle 1
W4Owner approval memo on the filing page; print the period file as a PDF binder; feed LOA ratios (Phase 4).After cycle 1

Why W1 first: the tie-outs cost little (they only read data you already have) and they catch the ledger-versus-documents mismatch before the first live 2550Q and 1701Q go out.

New tables (for the developer)

  • workpaper_files: client, period (month or quarter), status, locked_at
  • workpaper_schedules: file, ref (A–T), kind, prepared_by/at, reviewed_by/at
  • workpaper_adjustments: schedule, kind, amount, return line, reason, support document, created_by
  • workpaper_ticks: schedule, row key, tick (agreed to source, traced to ledger)
  • review_notes: file, schedule ref, row key, body, status, raised_by, cleared_by, reply

Schedules are computed, like worksheets today. Only sign-offs, ticks, adjustments and notes are stored. The file locks with the last return of the period, the same way worksheets lock now.

Decisions for you

  • W/P reference letters: keep A–T as drafted, or match the index of your audit working papers?
  • Tie-out tolerance before “Mark prepared” is blocked (₱1 rounding? ₱100?)
  • Must every schedule be reviewer-signed, or only B, C and T?
